# 디자인 시스템

출처: `refs/doum-key-visual.png` (앱 DOUM 키비주얼) + 앱 실화면.
**웹은 앱과 같은 서비스로 보여야 한다.** 여기서 벗어나는 색·모양을 새로 만들지 않는다.

> 아래 HEX는 캡처를 눈으로 읽은 근사값이다.
> 앱 소스나 원본 디자인 파일에서 정확한 값이 확인되면 이 표를 먼저 고친다.

---

## 1. 색

| 토큰 | 값(근사) | 쓰는 곳 |
|---|---|---|
| `brand` | `#00D5C8` 민트/틸 | 로고, 주요 CTA, 강조 배지, 포인트 컬러 |
| `brand-weak` | `#E6FAF8` | 배지 배경, 선택 상태, 옅은 강조 블록 |
| `bg` | `#FFFFFF` | 기본 배경 |
| `bg-tint` | `#F2FBFC` | 섹션 구분용 아주 옅은 민트. 히어로 하단 그라데이션 |
| `ink` | `#111111` | 제목, 로고 워드마크 |
| `text` | `#374151` | 본문 |
| `text-weak` | `#9CA3AF` | 캡션, 메타(날짜·거리) |
| `line` | `#EDEFF2` | 카드 테두리, 구분선 |
| `chip` | `#F3F4F6` | 필터 칩 배경 |
| `warn` | 배경 `#FEF3C7` / 글자 `#B45309` | "1/3명 지원" 같은 진행 상태 |
| `star` | `#FBBF24` | 별점 |

**규칙**
- 포인트 컬러는 `brand` 하나뿐이다. 두 번째 강조색을 만들지 않는다.
- 민트를 넓은 면적에 깔지 않는다. 배경은 흰색/`bg-tint`이고 민트는 점처럼 찍힌다.
- `refs/`의 카카오임팩트 계열 레퍼런스는 **편집 문법만** 본다. 노랑·검정 대비는 가져오지 않는다.

## 2. 모양

- **라운드가 크다.** 카드 `16~20px`, 배지·칩 `999px`(완전 알약), 버튼 `999px`.
- **테두리보다 그림자.** 카드는 `1px` 아주 옅은 선 + 넓고 흐린 그림자로 띄운다. 진한 선을 쓰지 않는다.
- 아이콘은 선 굵기가 얇고 끝이 둥근 계열.
- 캐릭터(흰 몸통 + 민트 머리카락)는 앱 자산이다. 웹에서 임의로 변형하지 않고,
  쓸 자리가 있으면 원본을 그대로 배치한다.

## 3. 타이포

- 한글 산세리프(Pretendard 계열). 제목은 굵게, 본문은 보통.
- 제목과 본문의 **굵기 차이로 위계를 만든다.** 크기 차이만으로 벌리지 않는다.
- 메타 정보(날짜, 거리, 이름)는 작고 옅게.
- 숫자·영문은 같은 서체 안에서 처리한다. 별도 영문 서체를 끌어오지 않는다.

## 4. 여백

- 카드 안쪽 여백을 넉넉히 준다. 정보를 촘촘히 채우지 않는다.
- 섹션 사이는 크게 비운다. 기획안의 "넓은 여백, 큰 타이포" 원칙을 여기서 지킨다.
- 배경색을 통째로 바꿔 섹션을 나누는 방식은 최대 1~2회까지만.

## 5. 웹에 옮길 때 주의

- 앱은 **정보 밀도가 높은 리스트 화면**이다. 웹 랜딩은 반대로 한 번에 하나씩 보여준다.
  카드 스타일은 가져오되 밀도는 가져오지 않는다.
- 앱 실화면을 그대로 캡처해 넣을 때는 기기 프레임(폰 목업)에 넣어 배치한다.
  키비주얼처럼 살짝 기울이는 연출은 히어로에서만 쓴다.
