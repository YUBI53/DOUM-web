마을 주민이 교육을 받아 돌봄매니저가 되고, 앱으로 도움이 필요한 이웃과 연결되며,

## 2. 기획은 두 번 있었다

이 프로젝트의 가장 중요한 배경이다. **1차 기획과 2차 기획이 다르고, 폴더의 문서 두 개가 각각 다른 기획을 담고 있다.**

| | 1차 기획 (2026년 5월) | 2차 기획 (2026년 8월, 현재) |
|---|---|---|
| 문서 | `docs/DOUM-MVP-PRD-v1.0.pdf` | `docs/앱기획서.pdf` ([NEW앱] 기획서) |
| 성격 | **일손 매칭** | **돌봄 매칭** |
| 돕는 사람 | 귀촌·단기 거주 **이주 청년** (Helper) | 마을에 사는 **주민** → 교육 → 돌봄매니저 |
| 받는 사람 | 다로리 마을 어르신 (70대 이상) | 돌봄이 필요한 이웃 (어르신·아동 등) |
| 보상 | **크레딧** (1단위 = 1원) | **활동비** (사업 예산에서 정산·출금) |
| 어르신 진입 | **전화 한 통** → AI 음성 에이전트 '포로리' → STT → 공고 초안 | 앱 (본인 또는 보호자 계정) |
| 매칭 방식 | 공고에 여러 청년이 **신청**, 운영자 승인 | 매니저가 **배정**, 시간 조율 후 확정 |
| 운영 주체 | 다로리인 / 중간지원조직 | 청도군 마을돌봄 사업 + ㈜다로리인 |
| 검증 질문 | "이주 청년은 크레딧 동기만으로 처음 만나는 어르신을 방문해 도움을 완료하는가?" | (문서에 명시 없음) |

### 왜 바뀌었나

정채윤이 전한 팀의 설명: `[대화 2026-08-30]`

- "원래 일손도움 앱이었다가 **도움에서 돌봄으로 확장**되면서 기획 방향이 바뀌었다."
- 팀명 **포로리**는 1차 기획의 AI 전화 에이전트 이름에서 왔다. 서비스명은 **DOUM**으로 확정. `[웹기획안]` `[CLAUDE.md]`
- 2차 기획서는 다른 팀원(이예슬)이 수정된 방향에 맞춰 새로 썼다.
- `refs/doum-key-visual.png`(키비주얼)는 1차 기획 때 만든 것이다. 디자인 스타일 참고용이지 현재 기획 화면이 아니다.

### 1차에서 이어지는 것

- **AI 전화(TTS/STT) 요청**은 1차 프로젝트에서 **실제로 구현해 봤다.** 2차에도 "최종 목표"로 유효하나, 현재 프로토타입에는 없다. 웹사이트에서도 메인으로 두지 않기로 했다. `[대화 2026-08-30]`
- "도움은 트랜잭션이 아니라 **관계의 시작점**"이라는 관점은 1차 문서의 것이지만, 팀이 지금도 이어진다고 봤다. `[PRD]` `[대화]`
- 1차 문서의 **기대 효과** 항목 (단기: 이주 청년 조기 적응·재이탈 방지, 어르신 일상 도움 수요 해소 / 중장기: 신뢰 자본 형성, 생활 아카이브 축적, 타 지역 확장) — **이주 청년·크레딧 프레임이라 그대로 못 쓴다.** 돌봄·주민·활동비 프레임으로 다시 써야 한다. `[PRD p.9]`

## 3. 현재 앱의 실제 구조

### 3-1. 문서에 있는 것 `[앱기획서]`

**역할 3개** — 돌봄 요청자 / 돌봄매니저 / 관리자

**돌봄매니저 등록 상태** — `applied`(지원 접수) → `trained`(교육 이수) → `active`(활동 가능)
- 지원 시 입력: 이메일·비밀번호·이름·연락처, 거주 읍·면, 자차 보유, 활동 가능 지역(복수, 최대 10개)
- 활동 지역은 청도군 9개 읍·면만 허용: 청도읍, 화양읍, 각남면, 풍각면, 각북면, 이서면, 운문면, 금천면, 매전면

**돌봄 요청 상태** — `requested` → `proposed` → `confirmed` → `completed` / `cancelled`
- 요청자가 유형·희망 일시·사유 입력 → 배정된 매니저에게 노출
- 매니저는 수락하거나 다른 시간 제안 → 요청자가 확정해야 `confirmed`
- "이 시간에 꼭 가야 해요" 스위치를 켜면 매니저가 시간 변경 불가
- 요청자와 매니저 간 메시지 대화 있음

**활동 인증 2단계** — 시작 인증(GPS·시각 자동 기록) → 종료 인증(GPS·시각 기록, 요청 완료 처리)
- 각 인증은 1회만. GPS 불가 시 수동 완료 처리 유지

**활동일지** — 인증을 거치면 대상자·활동일·시간·유형·장소·내용 초안이 **자동 입력**. 매니저는 서술·특이사항·사진만 추가
- 활동 유형: 일반 / 공동체 / 긴급
- 제출 → 검토 대기 → 관리자 승인 후 정산 반영. 반려 시 사유 확인 후 재제출
- 일지 양식은 **공식 활동일지 서식** 필드를 따른다

**정산·출금** — 잔액 = 승인 정산 총액 − (신청 중 + 지급 완료 출금). 잔액 초과 신청은 서버가 차단. 반려된 출금은 잔액으로 복귀

**돌봄매니저 홈 KPI** — 이번 달 예상 활동비, 전체 활동, 승인 완료, 검토 대기/반려

**관리자 역할** — 지원 심사·승인, 일지 검토·승인/반려, 정산, 지역별 매니저 배치 통계

### 3-2. 문서에는 없고 프로토타입·피그마에만 있는 것 `[프로토]` `[대화 2026-08-30]`

웹사이트를 만들면서 팀원에게 HTML 프로토타입(30여 화면, 작동함)과 피그마 디자인(41 프레임)을 받아 확인했다.
**`docs/앱기획서.pdf`에는 아래가 없다.** 앱은 문서보다 더 나아가 있다.

| 개념 | 내용 |
|---|---|
| **정기 돌봄 / 긴급 돌봄** | 요일·시간을 정해두면 같은 매니저가 매번 찾아오는 것이 **기본**. 긴급은 따로 요청. 예: "화·목 아이 픽업", "월·수 등하원 동행". 정기는 이번 주만 시간 변경·쉬기 가능, 요일 자체 변경은 변경 요청 |
| **보호자 계정** | 가입 시 `본인으로 가입` / `보호자로 가입` 선택. 떨어져 사는 가족이 대신 요청하고 함께 확인 |
| **연결 코드** | 본인과 보호자가 각각 계정을 만든 뒤 코드로 연결. 상대방 승인 필요. 연결되면 같은 일정·일지를 함께 봄 |
| **돌봄방** | 요청자별 방. 일정·내용·채팅·일지가 한곳에 모임. 예: "김아이 돌봄방", "김어르신 돌봄방" |
| **매니저 활동 조건** | 활동 가능 시간, 이동 범위(거주지 기준 10km) 설정 |
| **매니저 이력** | 캘린더형 활동 이력, KPI(활동 횟수·시간·정산 예정액) |
| **아동 돌봄 비중** | 프로토 예시가 아이 픽업·등하원 동행 위주. 팀 판단: "어르신이 주는 아니다. 도움에서 돌봄으로 확장된 것이고, 아동이 주까진 아니어도 꽤 나온 포지션은 맞다." `[대화 2026-08-30]` |

**돌봄 유형** (앱과 동일) — 병원·이동 라이딩 / 동행 / 집안일 도움 / 식사 지원 / 아이 돌봄 / 기타 `[CLAUDE.md]` `[프로토]`

**관리자 화면은 프로토타입에 없다.** 41 프레임 전부 요청자·매니저 화면이다.

## 4. 웹 작업 중 확인·정정된 사실

신청서를 쓸 때 헷갈리기 쉬운 것들이다.

- **폐기된 개념** — 요청 카드의 "거리(1.0km)", "지원자 수(1/2명)"는 1차 기획(여러 청년이 한 공고에 지원)의 개념이다. 2차는 매니저 **배정** 구조라 맞지 않는다. `[대화 2026-08-30]`
- **이름 불일치** — 앱기획서와 프로토 본문에는 아직 '다로리'가 남아 있다(로고는 DOUM). 팀에 정리 필요하다고 전달함. 서비스명은 **DOUM**으로 간다. `[대화 2026-08-30]`
- **사업 명칭 불일치** — 앱: "청도군 돌봄매니저 양성사업" / 확인되는 공식 명칭: "**2026년 마을돌봄공동체 육성 지원사업**". 어느 쪽이 정식인지 미확정. `[CLAUDE.md]`
- **활동비 20,000원**은 앱의 데모값이다. 실제 단가 미확정. `[CLAUDE.md]`
- **실적이 없다.** 누적 이용 건수, 참여자 수 같은 수치를 만들어 쓰지 않는다. `[CLAUDE.md]`
- '다로리'는 서비스명이 아니다. **마을 이름**(청도군 화양읍 다로리)과 **회사명**(㈜다로리인)으로만 쓴다.

## 5. 파트너 사실 `[CLAUDE.md]` `[웹기획안]`

**청도군 마을돌봄 사업**
- 청도군이 발주, ㈜다로리인이 위탁 운영
- 재원은 지방소멸대응기금
- 마을 안에서 돌봄매니저를 길러내고 활동한 만큼 활동비 지급
- DOUM은 이 사업 **위에 얹히는** 매칭 서비스 (사업이 사람을 길러내고, 앱이 그 사람을 이웃과 잇는다)

**㈜다로리인**
- 청도군 화양읍 다로리 마을의 사회적기업, 농촌소멸 대응
- 카페 다로리, 마을학교, 마을쌤·맘셰프 양성 과정 운영
- 청도군·다로리인 **로고 사용 승인은 미확인**

## 7. 신청서 작성 프레임 (워크스테이션 공모)

`[대화 2026-09-13]`

- **과제**: '워크스테이션' — 사회혁신 기반 프로젝트 공모. 계획서를 내면 선정에 따라 지원금.
- **단락**: 팀원 소개 / 팀이 정의하는 사회혁신 / 해결하고자 하는 문제 / … / **최종목표 및 기대효과** ← 정채윤 담당
- **팀장 지시 원문**:
  > "지금까지 현장 멘토링이랑 상호 피드백(어려움 접수)까지만 진행했고, 웹사이트나 앱 개발을 이번 학기에 하겠다 이런 식으로 목표를 잡고 작성하면 될 것 같습니당"

**해석** — 신청서의 시점을 이렇게 잡는다.

| | 신청서에서의 위치 |
|---|---|
| 현장 멘토링, 상호 피드백(어려움 접수) | **지금까지 한 것** |
| 웹사이트 제작, 앱 개발 | **이번 학기에 할 것** (목표) |

웹사이트와 앱 프로토타입은 실제로는 이미 있지만, **신청서에서는 이번 학기 목표로 쓴다.**
따라서 '최종목표 및 기대효과'는 "이번 학기 안에 웹사이트와 앱을 만들어 ○○에 이르겠다"는 구조가 된다.
구체적 목표·효과 문구는 정채윤과 함께 새로 쓴다. 이 문서는 사실만 담는다.
